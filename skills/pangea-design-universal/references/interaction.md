# 交互规则

> 来源：Pangea 设计规则，并吸收 [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines) 中与技术栈无关的通用条目（已改写为中文并按 Pangea 取值调整；与 Pangea 冲突或仅适用于 Vercel 品牌的条目未采纳，见文末）。
>
> 标 **【硬】** 的条目属于硬约束，交付前必须满足；其余为推荐约束，偏离时在交付说明中写明理由。

## I1 反馈与加载

- **【硬】每个操作都要有反馈**：点击后立即有视觉变化（按下态、加载态或结果），不能让用户怀疑「点上了没有」。
- **加载中的按钮**：显示加载指示，**保留原文字**（或改成进行中文案，如「保存中…」），宽度不跳动；进行中禁止重复点击。
- **避免加载闪烁**：加载指示 / 骨架屏延迟约 150–300ms 再出现；一旦出现，至少保持约 300–500ms。响应很快时用户什么都看不到，比一闪而过更好。
- **骨架屏与最终内容结构一致**，加载完成时不发生布局跳动。
- **乐观更新**：成功概率高的操作（勾选、收藏、排序）先更新界面再等服务端；失败时提示错误并回滚，或提供撤销。
- 进行中状态和「会打开下一步」的菜单项以省略号结尾：「加载中…」「重命名…」。使用省略号字符 `…`，不用三个句点。
- 提交类请求（新增 / 修改 / 删除）目标响应时间 < 500ms；超出时必须有明确的进行中反馈。

## I2 数据区状态

- **【硬】每个数据区都要设计这些状态**，不能只做有数据的样子：

  | 状态 | 要点 |
  |---|---|
  | 首次无数据 | 说明这里会出现什么，并给出第一步操作（如「创建第一个项目」） |
  | 筛选 / 搜索无结果 | 和「首次无数据」区分开；提供「清除筛选」 |
  | 加载中 | 见 I1 |
  | 加载失败 | 说明发生了什么 + 「重试」；不要只显示空白 |
  | 无权限 | 说明缺少什么权限、找谁申请 |
  | 数据很少 / 很多 | 内容稀疏时不显得空洞；数据很多时有分页、虚拟滚动或「加载更多」 |

- **【硬】没有死路**：任何状态都要给出下一步或恢复路径。
- 使用模拟数据演示时，提供查看各状态的方式（如 URL 参数 `?state=empty|error|forbidden`），便于评审。
- **经得起用户内容**：布局要能承受很短、正常和超长的内容。超长文本截断时用省略号，并提供完整查看方式（悬浮提示、展开或详情）。

## I3 危险操作

- **【硬】删除、作废、批量变更等不可逆操作必须二次确认，或提供有时间窗口的撤销。**
- **确认还是撤销**：操作会对外产生影响（发通知、发邮件、调用外部系统）或无法回滚的，用二次确认；只影响本地数据、可以完整回滚的，优先用「撤销」（执行后给出带撤销按钮的消息，几秒内可撤回），少打断。
- 确认对话框写清后果（删什么、影响多少条、能否恢复），确认按钮用 danger 样式并写具体动作（「删除 3 条记录」而不是「确定」）。宽度见 [C2](design-core.md#c2-对话框宽度档位硬约束)。
- 危险按钮不做默认焦点，回车不应直接触发删除。
- **有未保存修改时离开页面要提醒**，避免数据丢失。

## I4 表单

**字段**

- **【硬】每个控件都有标签**（可见标签，或至少有可访问名）；点击标签能聚焦到对应控件。
- 复选框、单选框的标签和控件共用一个点击区，中间没有点不到的空隙。
- 占位提示（placeholder）用来给**示例或格式**（如「例：13800000000」），不能代替标签。
- 用正确的输入类型和输入模式（邮箱、电话、数字、网址），移动端会弹出合适的键盘；设置 `autocomplete` 和有意义的 `name`，让浏览器能自动填充。
- 验证码、用户名、邮箱等字段关闭拼写检查。
- **【硬】不禁止粘贴。**
- **不要拦截按键**：即使字段只接受数字，也允许输入，再用校验提示说明，比「按了没反应」更容易理解。
- 提交前去掉首尾空格，避免输入法自动加的空格触发莫名其妙的错误。
- 移动端输入框字号不小于 16px（`--font-size-title-1`），否则 iOS Safari 聚焦时会自动放大页面。

**提交与校验**

- **不要预先禁用提交按钮**：允许提交不完整的表单，借此把校验错误展示出来。
- 提交开始后才禁用按钮，并显示加载状态；请求要能防重（服务端幂等或前端锁）。
- **【硬】错误显示在对应字段旁边**；提交失败时把焦点移到第一个出错的字段。
- 同一表单校验时机保持一致（失焦校验或提交校验），见 [C7](design-core.md#c7-组件选型速查)。
- 只有一个输入框时，回车即提交；多行文本中回车换行，`Ctrl / ⌘ + Enter` 提交。
- 非登录字段（如搜索）不要触发密码管理器；验证码字段允许粘贴一次性密码。

## I5 焦点与键盘

- **【硬】所有流程都能只用键盘完成**，交互模式参照 WAI-ARIA Authoring Practices。
- **【硬】焦点清晰可见**：每个可聚焦元素都有可见、不被遮挡的焦点样式。优先用 `:focus-visible`（鼠标点击不出现，键盘操作才出现）；控件组用 `:focus-within`。不得只写 `outline: none` 而不给替代样式。
- 固定的头部、底部、浮层不能挡住当前聚焦的元素。
- **对话框 / 抽屉**：打开时焦点移入并限制在内部，`Esc` 关闭，关闭后焦点回到触发它的元素。
  - 焦点移到哪：有输入项时给第一个输入项；确认类给「取消」（危险按钮不做默认焦点）；纯展示内容给对话框本身（设 `tabindex="-1"`）。
  - 叠层时 `Esc` 只关最上层，焦点回到下层中的触发元素。
  - 触发元素在操作后被移除（如行内按钮变成结果文字）时，焦点回到它所在的区块或下一个同类元素，不落到页面开头。
- 桌面端页面只有一个主要输入时可以自动聚焦；移动端一般不自动聚焦（弹出键盘会导致布局跳动）。
- 快捷键按平台显示符号（⌘ / Ctrl），并考虑非 QWERTY 键盘布局。

## I6 点击区与指针

- 视觉大小与可点击区域一致；**视觉小于 24px 的控件，点击区扩大到至少 24px**；移动端至少 44px。
- **没有死区**：看起来能点的部分都要真的能点。
- **跳转用链接**（`<a>`），保证 `Ctrl / ⌘ + 点击`、中键、右键新标签打开等浏览器行为；不要用按钮或 `div` 模拟跳转。
- 拖拽、滑动、双指缩放等手势都要有点击和键盘的替代方式（手势本身不可替代的除外）；拖拽过程中禁止文字选中。
- 控件上设置 `touch-action: manipulation`，避免双击缩放。
- **说明优先放在界面里**；悬浮提示（tooltip）是最后手段。一组相邻控件的 tooltip，第一个延迟出现，之后在同组内移动不再延迟。

## I7 状态保留与导航

- **筛选、标签页、分页、展开的面板等状态写进 URL**，刷新、分享链接、前进 / 后退都能还原。
- 前进 / 后退时恢复之前的滚动位置。
- 页面标题（`<title>`）反映当前内容，格式建议「页面名 · 系统名」。
- 用锚点跳转的标题设置 `scroll-margin-top`，不被固定头部挡住。
- **【硬】不禁用浏览器缩放**（不使用 `maximum-scale=1` / `user-scalable=no`）。
- 对话框、抽屉内滚动时设置 `overscroll-behavior: contain`，滚到底不带动背后的页面。

## I8 动效

- 时长和缓动只用变量：`--transition-duration-1`～`5`（0.1–0.5s）、`--transition-timing-function-*`。微交互（hover、按下）用 0.1–0.2s，面板进出用 0.2–0.3s。
- **只在能说明因果关系时使用动效**（从哪来、到哪去、什么变了），不为装饰而动。
- **【硬】支持减弱动效**：`prefers-reduced-motion: reduce` 时去掉或大幅减弱位移、缩放类动画。
- 优先动画 `transform` 和 `opacity`；避免动画 `width`、`height`、`top`、`left` 等会引起重排的属性。
- **不写 `transition: all`**，只列出需要过渡的属性。
- 动画可被用户操作打断；变换原点放在它「出发」的位置（如下拉菜单从触发按钮展开）。
- 自动播放且超过 5 秒的动态内容要提供暂停 / 关闭。
- 优先用 CSS 实现动画，其次 Web Animations API，再其次 JS 动画库。

## I9 内容与可读性

- 需要对比的数字（金额、统计、表格数值列）用等宽数字：`font-variant-numeric: tabular-nums`，并右对齐。
- 状态不只靠颜色（[C6](design-core.md#c6-状态不只靠颜色传达)）；纯图标按钮有 `aria-label`；装饰性图标设 `aria-hidden`。
- **先用语义元素再用 ARIA**：`button`、`a`、`label`、`table`、`h1–h6` 优先。标题层级连续；长页面提供「跳到主要内容」链接。
- 日期、时间、数字、金额按用户的语言区域格式化；语言按浏览器语言设置判断，不按 IP 或定位。
- 品牌名、产品名、代码、技术标识加 `translate="no"`，避免被浏览器自动翻译。
- 数字和单位之间、快捷键组合之间用不换行空格（`10&nbsp;MB`），避免断在两行。
- 中文使用全角标点；避免段落最后一行只剩一两个字。

## I10 可用性文案

> 这里只管「让用户看懂、能操作」的通用要求；品牌语气目前没有规范，见 [brand.md](brand.md)。

- 按钮写具体动作：「保存配置」而不是「确定」，「删除 3 条记录」而不是「继续」。
- **错误提示要说明怎么解决**：不只说「密钥无效」，而是「密钥不正确或已过期，请在账号设置中重新生成」，并给出可点击的入口。
- 用行动导向、简洁的表述，能少一个字就少一个字。
- 同一个概念全程用同一个词，不在不同页面换说法。
- 计数用阿拉伯数字（「8 个部署」）；同一场景的金额小数位保持一致。
- 出错时语气平和、以解决问题为导向，不责备用户。

## I11 视觉细节

- **嵌套圆角**：内层圆角 ≤ 外层，且尽量同心。例：8px（`--border-radius-large`）的卡片内放 4px（`medium`）的控件。
- 在彩色底上，边框、阴影、文字向同一色相偏移，不用纯灰。
- 图表用对色盲友好的配色组合，并配图例文字（扩展色板见 [C9](design-core.md#c9-取值铁律)）。
- 暗色主题在根元素设置 `color-scheme: dark`，让滚动条等浏览器控件同步变暗；可用 `<meta name="theme-color">` 让浏览器界面与页面底色一致。
- 原生 `<select>` 显式设置背景色和文字色，避免 Windows 暗色模式下对比度出错。
- 只显示有用的滚动条；修好溢出问题，不留多余的滚动条。
- 布局交给 CSS（flex / grid）完成，不用 JS 测量尺寸来排版。
- 文字与图标并排时调整粗细、大小或颜色，使二者视觉重量协调。

## I12 性能体验

- 图片设置明确的宽高，预留空间，避免加载后布局跳动；首屏以外的图片懒加载。
- 很长的列表用虚拟滚动或 `content-visibility: auto`。
- 耗时计算不放在主线程，避免页面卡顿。
- 循环动画优先用静音视频代替 GIF，并提供静态替代。

## 未采纳的条目

以下条目来自 Vercel Web Interface Guidelines，因与 Pangea 冲突或不通用而未采纳：

| 条目 | 原因 |
|---|---|
| 阴影至少两层叠加 | 阴影只用 Pangea 的阴影变量（单层） |
| 对比度优先用 APCA | Pangea 以 WCAG 正文 4.5:1 为准（[C6](design-core.md#c6-状态不只靠颜色传达)） |
| hover / active 对比度要高于默认态 | 主题中主色按钮 hover 用更浅的 `primary-5`，以主题为准 |
| 占位提示以省略号结尾 | 中文界面习惯不同，占位提示改为给出示例或格式（I4） |
| 标题、按钮用英文 Title Case；用 `&` 代替 and；等 Vercel 品牌文案约定 | 仅适用于英文与 Vercel 品牌 |
| 用 `maximum-scale=1` 防止 iOS 输入放大 | 与「不禁用缩放」冲突，改为输入框字号 ≥ 16px（I4） |
| React / Next.js 专属条目（水合、特定状态库、渲染性能工具） | 与技术栈相关 |
