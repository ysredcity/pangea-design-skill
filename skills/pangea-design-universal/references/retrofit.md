# 改造已有界面

用于**已经存在的界面**：原型、演示页、已开发的工程。目标是让它在取值、组件状态、交互上符合 Pangea，**而不是重新设计它**。新做界面不读本文件。

默认流程：R0 前提 → R1 基线 → R2 盘点 → R3 映射表（**确认后再动手**）→ R4 分批执行 → R5 验收。

---

## R0 前提：改源码，不改产物

- 要改的是**可维护的源文件**：`.css / .scss / .vue / .tsx / .html` 等。
- 拿到的是打包产物（单文件离线版、`dist/`、样式被压成脚本字符串、带哈希的类名）时，**先向用户要源码**。拿不到时：
  - 盘点前先把样式与页面**只读解出**到工作目录（如把脚本里的 CSS 字符串用 `JSON.parse` 还原成 `.css`），对解出的文件跑 lint；
  - 改动只做**覆盖层**：在产物的样式入口末尾追加一段样式（`tokens.css` + 按映射表重定义变量 + 按选择器覆盖散写值），不逐处改产物内的值；
  - 内联 `style=""`、脚本拼接的颜色覆盖层压不住，需要改产物字符串时，列出数量和位置，**用户同意后再改**，不用 `!important` 大面积硬压；
  - 覆盖层下原值仍留在产物里，lint 仍会扫到。两种做法二选一，在映射表里让用户选：
    - **只加覆盖层**：lint 只对覆盖层本身要求 ERROR 0，产物中的残留按「被覆盖 / 未覆盖」列入交付说明，靠截图核对效果；
    - **按映射表程序化改写产物中的样式字符串**（写构建脚本，不手工逐处改）：可以做到整体 ERROR 0，改动面大，须用户明确同意；
  - 交付说明写明「改的是产物，重新打包会丢失，需同步回源码」。
- 只有截图、没有代码时，只能出改造建议，不能执行改造。

## R1 基线：先记下哪些东西不能变

动手前记录，改完逐条核对：

| 项目 | 记录什么 |
|---|---|
| 功能 | 每个可操作的入口与它的结果（按钮、链接、表单提交、筛选、切换、弹窗） |
| 内容 | 文案、数据、字段、列、数量；业务数据即使看起来有误也**原样保留**，只在说明里提示。记录的是**渲染后**的可见文字：改 `text-transform` 等会改变显示文字的样式时同样要核对 |
| 结构 | 页面与区块的层级、导航方式、区块顺序 |
| 画面 | 默认态截图；有弹窗、展开、空态等关键状态的各截一张 |

**默认不改**：文案、数据、功能、信息架构、区块顺序、导航形态、页面数量。确实要改（如危险操作补二次确认、补空 / 错误态）时，在映射表的「交互缺口」里单独列出，用户同意后再做。

## R2 盘点：先看清它的取值体系

```bash
node <本 skill 目录>/scripts/lint-tokens.mjs --inventory <源码目录>   # 原型自己定义的变量层
node <本 skill 目录>/scripts/lint-tokens.mjs --summary   <源码目录>   # 违规按值汇总 + 建议档位
```

先判断它属于哪种体系，决定改动落点：

| 现状 | 改动落点 |
|---|---|
| **有自己的变量层**（`:root { --bg-base: #f5f7fa; … }`） | **在变量定义处改指向 Pangea 变量**，引用处不动。一处改全局，改动面最小 |
| 用组件库默认主题（Element Plus / antd / Arco 等） | 引入 [adapters.md](adapters.md) 中对应的适配文件，再处理散写的值 |
| Tailwind | 换成适配文件中的主题；任意值 `text-[#333]` / `p-[13px]` 逐个改为档位类 |
| 值散写在各处 | 先建一个映射表，按值批量替换；同一个值在不同位置可能承担不同角色，按角色而不是按值替换 |

`--summary` 的「建议」只是就近档位，颜色不给建议——颜色要按 R3 的角色判断。它把每类问题分成「来自变量」（改变量定义即可消除）和「散写」两部分计数。

lint 覆盖不到、需要人工补盘的：控件高度（对照 [C5](design-core.md#c5-控件密度)）、脚本里拼接的样式字符串、用 emoji 或字符当图标、产品标识与 favicon。

**变量同名冲突**：原型自定义的变量与 Pangea 同名（如原型的 `--color-secondary` 是紫色强调，Pangea 的是次按钮底色），接入 `tokens.css` 后会互相覆盖。lint 以 W7 提示；改造时把原型变量改名，引用处随之改。

## R3 映射表：先映射、确认，再替换

输出一张表交给用户确认（单页、只涉及取值、且没有下面「需确认」项时，可以直接执行并在交付说明中附表）：

| 原值 / 原变量 | 用途 | Pangea 变量 | 备注 |
|---|---|---|---|
| `--color-primary: #6366f1` | 主按钮、选中态 | `rgb(var(--primary-6))` | hover 5 / active 7 |

### 颜色：按角色映射，不按色值远近

| 原型里的角色 | Pangea 变量 |
|---|---|
| 品牌主色、主操作、选中态、进度 | `--primary-6`（hover `--primary-5`、按下 `--primary-7`、浅底 `--color-primary-light-1`） |
| 文字链接 | `--link-6` |
| 标题 / 正文 / 次要 / 禁用文字 | `--color-text-1` / `-2` / `-3` / `-4` |
| 页面底、卡片、抬升层、浮层 | 按 [C3](design-core.md#c3-页面背景分层)：`--color-bg-1` … `--color-bg-5`、`--color-bg-popup` |
| 浅灰块（图标底、计数底、槽） | `--color-fill-1` … `--color-fill-4` |
| 描边 / 分割线 | `--color-border-1` … `--color-border-4` |
| 成功 / 警告 / 危险 / 信息 | `--success-6` / `--warning-6` / `--danger-6` / `--link-6`；浅底用 `--color-*-light-1` |
| 遮罩 | `--color-mask-bg` |
| 分类色（头像、图表系列、类目标签） | 扩展色板的 6 阶（`--cyan-6`、`--purple-6`、`--orange-6` …）；同一类目在整个产品里固定同一色 |
| 白底上的反白文字 | 主按钮文字 `--btn-primary-color-text`，其它用 `--color-white` |

映射时的细则：

- **半透明色**：底色优先用 `--color-*-light-1` … `-4` 这类现成浅色；焦点环、图形、叠层确需透明度时写 `rgba(var(--x-6), α)`。文字不用半透明色，彩色底上的白字用不透明的 `--color-white`。
- **近黑的蓝灰 / 深灰**：属于中性色，按用途归入 `--color-text-*`、`--color-fill-*`、`--color-neutral-*`，不并入主色。
- **渐变转纯色**：取渐变中承担该元素角色的颜色（通常是起始色）再按角色映射；只起氛围作用的渐变直接删除。
- **分类色避开状态色**：Pangea 中 `orange-6` = `warning-6`、`green-6` = `success-6`、`red-6` = `danger-6`、`arcoblue-6` = 信息色，`cyan-6` 与主色相近。分类色从 `purple`、`pinkpurple`、`magenta`、`gold`、`lime`、`blue` 等取，避免被读成状态。
- **正文里的状态文字**（白底上写「已逾期」「通过」等文字，不在标签 / 徽章内）：取对比度 ≥ 4.5:1 的一阶——`success-8`、`warning-8`、`danger-7`；标签、徽章、图标仍按组件规格用 `-6`。

**需确认**（映射表里单独标出，问用户）：

- **第二强调色**（如原型用「靛蓝主色 + 紫色辅色」）：操作类一律并入 `--primary-*`；只用于标识的（如 AI 标识）可保留为**一个**扩展色系，且不用于按钮、链接、选中态。
- **渐变、发光、毛玻璃、粒子背景**：Pangea 没有定义这类装饰。默认收敛为纯色 + Pangea 阴影；用户要求保留氛围时，只把颜色换成 Pangea 色，形态不扩大，并在交付说明列出。
- **深色原型**：Pangea 默认亮色。原型默认深色时问用户：改为亮色，或保持深色并在根元素加 `data-theme="dark"` 使用 Pangea 暗色值。不自造深色值。
- **局部深色区**（亮色页面中的视频区、代码区、终端等）：保留深色时在该区域根节点加 `data-theme="dark"`，区域内只用语义变量，得到 Pangea 暗色值；不自造深色值。⚠ 原型在 `:root` 上定义的别名（如 `--text-primary: var(--color-text-1)`）已按亮色算好再继承下来，区内拿不到暗色值——区内直接写 Pangea 变量，或在区域根节点上重新声明这些别名。
- **模拟第三方界面**（手机框里的飞书 / 微信消息样例、第三方客户端截图式还原）：外围页面按 Pangea 改；模拟区内部属于演示内容，默认保持原外观，在交付说明中列为豁免。豁免的样式用注释 `pangea-lint-disable` / `pangea-lint-enable` 包起来，lint 不检查这一段；只用于已确认的例外，不用来绕过检查。模拟区内不出现第三方 Logo 图形，只用文字称呼。
- **原型的品牌标识**：换成 `assets/brand/` 中的标准文件，见 [brand.md](brand.md)。换 Logo 改变首屏构图时（如原型用大图标做主视觉）先说明。原位置放不下标准 Logo（规范未给最小尺寸，缩到字母难以辨认即视为放不下）时，不硬缩，改放到顶栏或该位置只保留系统名，并向用户确认。
- **emoji / 字符当图标**：导航、按钮、卡片标题、状态等功能性图标换成 Lucide 中含义相同的图标（[icons.md](icons.md)）；正文、消息内容、用户数据中的 emoji 属于内容，保留。脚本生成的图标一起换：用 `textContent` 写入的位置要改成插入 SVG 元素，否则会显示成源码文字；脚本会读取或写回的状态字符（如用 `textContent` 在「✓」和「○」间切换），改了会与脚本逻辑对不上，保留并在交付说明中列出。
- **组件规格里没有的按钮类型**（如成功色实底按钮）：按它在组里的角色映射——唯一主操作用主按钮，语义靠文案和图标表达；不自造颜色类型。

### 对比度

替换颜色后重新检查文字对比度（规则见 [C6](design-core.md#c6-状态不只靠颜色传达)）：

- 原型用深一档主色写的**强调文字**，映射到 `primary-8`，不要映射到 `primary-6`（白底约 2.9:1）；≥ 24px 的标题强调可用 `primary-7`（大字号只需 3:1）。按钮、链接、图标、选中态仍按组件规格用 `primary-6`。
- 原型的弱提示文字映射到 `--color-text-3` 前，判断是否承载必要信息；承载的用 `-2`。`--color-text-4` 只用于禁用。

### 尺寸：就近取档

| 类别 | 档位 | 规则 |
|---|---|---|
| 字号 | 12 / 13 / 14 / 16 / 20 / 24 / 36 / 48 / 56 px（`--font-size-*`） | 就近；**低于 12px 一律改为 12px**；与两档等距时，正文取小一档、标题取大一档 |
| 间距 | `--spacing-*`（2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 32 …） | 就近；等距时取小一档；组件内边距优先用组件级变量（`--btn-size-*`、`--table-size-*`）。⚠ **按值对应，不按序号**：原型常见的 `--space-4` = 16px 对应的是 `--spacing-7`，不是 `--spacing-4`（8px） |
| 圆角 | 2 / 4 / 8 px、`50%`（`--border-radius-small / medium / large / circle`） | **先按角色，再看数值**：控件（按钮、输入、标签、徽章、tabs）用 `medium`，容器（卡片、面板、弹窗、浮层）用 `large`，圆形头像 / 圆点用 `circle`；同一个原变量被两类元素共用时，按选择器拆开映射。胶囊形（999px）不保留，组件规格本身是全圆角的（如开关轨道）除外 |
| 控件高度 | 24 / 28 / 32 / 36 px（`--size-mini / small / default / large`） | 按 [C5](design-core.md#c5-控件密度) 的密度档，不按原高度就近 |
| 阴影 | `--shadow1-*` / `--shadow2-*` / `--shadow3-*` | 下拉、气泡、消息等浮层用 `--shadow2-down`（见 [components.md](components.md)）；其它按原阴影的大小就近取档；多层或彩色阴影合并为一层黑色阴影 |
| 动效时长 | `--transition-duration-1` … `-5`（100–500ms） | 就近；等距时颜色 / 透明度类变化取小一档，位移 / 展开类取大一档；超过 500ms 的环境动画（循环流动、粒子）默认去掉，加载类循环（转圈、骨架闪烁）用 `--transition-duration-loading`；表示「在线」「进行中」的状态呼吸 / 脉冲不是加载，保留原周期（lint 的 W1 提示在交付说明里解释），只把缓动换成 Pangea，并在 `prefers-reduced-motion` 下停掉；`delay` 与 `prefers-reduced-motion` 里的极短时长不改 |
| 缓动 | `--transition-timing-function-standard / decelerate / accelerate / overshoot / linear` | 一般过渡用 `standard`，进入用 `decelerate`，离开用 `accelerate`，回弹用 `overshoot` |
| 层级 | `--z-index-*` | 弹层（下拉、对话框、抽屉、消息）按类型取；页面骨架的吸顶、侧栏、顶栏（100–999，低于弹层）保留原值和先后顺序，交付说明里解释 lint 的 W2 提示；组件内局部层叠（< 100）不改 |
| 字体 | `--font-family`、代码 `--code-family` | 原型自定义的展示字体改为 `--font-family`；`--code-family` 只用于代码。原型用等宽字体排数字、编号、时间时，改为 `--font-family` + `font-variant-numeric: tabular-nums`，不换成 Consolas / Menlo |

字重、行高、字距不在档位约束内，保留原值；正文行高不足 1.5 时调到 `--line-height-base`。页面骨架尺寸（侧栏宽、顶栏高、内容最大宽）不在档位约束内，默认保留。

**无障碍偏好查询**（`prefers-contrast: more`、`prefers-reduced-motion`）里的覆写保留，只把其中的颜色换成更深一档的 Pangea 变量。

## R4 分批执行，每批核对

| 批次 | 做什么 | 完成标准 |
|---|---|---|
| 1 取值 | 接入 `tokens.css`（或适配文件）；按映射表改变量层，再清理散写的值；品牌标识、装饰收敛 | `lint-tokens.mjs` ERROR 为 0（只加覆盖层时按 R0 只对覆盖层要求） |
| 2 组件状态 | 对照 [components.md](components.md) 调按钮、输入、表格、标签、弹窗等的尺寸与 hover / 聚焦 / 禁用 / 错误态 | 各状态取值与规格一致 |
| 3 交互缺口 | 只做映射表里用户同意的条目，按 [interaction.md](interaction.md) 的【硬】项补齐 | 逐条可演示：每条写「触发 → 出现 → 取消不生效 → 确认生效」或键盘焦点序列的自动化验证，改造前后各跑一次 |

每批结束都做：

1. 跑 lint，记录 ERROR / WARN 数量变化；
2. 截图，与基线对比：**布局与区块顺序不变**，变化只来自取值；字号上调（如 10 / 11px → 12px）后检查是否出现新的换行或截断，出现时先在档位内收窄间距，仍不行再停下问；
3. 对照 R1 基线核对功能、文案、数据，有出入先修复再进入下一批。

改着改着发现需要动布局或结构时，停下说明原因，等用户决定，不顺手改。

批次 3 补充：

- 新增的确认框、无结果态等**按需创建或默认隐藏**，默认画面与基线保持一致，便于清单比对。
- 有源码时在原处理函数里调用确认 / 撤销；只能改产物时，可以在原操作之前拦截（确认后再放行同一次操作），并在交付说明写明回写源码时要改成前一种写法。
- lint 只查样式取值，查不到对话框宽度、按钮文案（如「确定」）、脚本里创建的元素，这些靠自动化演示与人工自检。

## R5 验收与交付说明

交付说明包含：

- 改造前后的 lint 汇总（ERROR / WARN 数量）；
- 已确认的映射表；
- 保真核对结果：功能、文案、数据、结构是否全部保持；
- 没有改的地方及原因（用户未同意、需要源码、规范未定义）；
- 偏离推荐约束的地方及理由。
